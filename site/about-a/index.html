How I work

  1. 01

    Read the source first

    Specs, backend rules, regulation. At MilSOFT I designed from the system documents, so no screen offered an action the backend would refuse.

  2. 02

    Look past direct competitors

    For Backlot I compared CMSs, video review tools and GitHub pull requests. The review loop came from code review, not from another CMS.

  3. 03

    Design the unhappy path

    Broken deliveries, wrong specs, rejected work. The edge case belongs in the design file, not in a support ticket.

  4. 04

    Check it against the real thing

    I prototype in code with Claude to see how a flow behaves with real states before anyone builds it.
